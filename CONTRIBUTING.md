# Contributing

1. Create a feature branch.
2. Keep data, model and UI changes separated where practical.
3. Add or update tests.
4. Run the repository checks before opening a pull request.
5. Never commit private portfolio, tenant, title, valuation or credential data.
6. Document model assumptions, units, dates and evidence sources.
7. Label synthetic data and synthetic-trained models explicitly.

Pull requests should describe model impact, data requirements, validation performed and rollback considerations.
